# PLAN — Phase 18: Production Hardening, Recovery, Security & Operational Resilience

Authority: /go/app/src/Phase 18 Production Hardening.md (WBS §18.1–18.234 + DoD L3779-3903). Project root: /go/app/src (Go module `overseer`).

Decomposition: bottom-up (pure domain primitives → configuration / persistence → services → wiring → fault / chaos / endurance tests → acceptance). One behavior per task. The WBS TDD tests exist before implementation. Phase 18 adds very little new functionality; it proves Phases 1–17 stay correct when the environment is not.

Inherited (Phase 17 COMPLETE 2026-10-09; record in TASK_ARCHIVE.md):
- **Engine:** driver lease with a fencing epoch (executions.driver_owner / driver_expires_at / driver_epoch; EngineRepository Acquire / Renew / Release / holds-driver check). Step hooks (intent / dispatch / dispatched / validation / checkpoint / checkpoint-committed / hardening:*). RecoverExecutions abandons RUNNING validation runs at startup.
- **Phase 12 dispatch rows:** status PENDING / SENDING / WAITING / COMPLETED / FAILED / CANCELLED / UNKNOWN, plus delivery DEFINITELY_NOT_SENT / SENT_RESPONSE_RECEIVED / DELIVERY_UNKNOWN. Final rows are immutable, and an unknown delivery is never resent. The worker prompt hash is verified before dispatch.
- **Validation (valrun):** process group (Setpgid), output cap, outcomes PASS / FAIL / INFRA_ERROR / NOT_CONFIGURED.
- **Repository and files:** gitcheckpoint uses trailer-keyed commits with crash reconciliation. Statefile safe_rel_path uses EvalSymlinks plus atomic write.
- **Audit and web:** audit_events (seq, immutable trigger) and the LiveEventFeed. The web security chain is headers / session / CSRF / body limit / rate limit / authorize / audit, plus /health and /ready.
- **Data and config:**
  - MetricsService is a project read model only.
  - The migration runner uses a transaction per migration, with no schema-compatibility check and no advisory lock.
  - The pgx pool has a fixed MaxConns of 10.
  - Config.Validate returns only the first error, and there are no profiles.
  - Global prompt templates and the default workflow are not seeded at boot.
- **Environment:** the box has no pg_dump / psql / docker. PG is 17.5 and the test role is a superuser.

Phase 17 open decisions handled here:
- DELIVERY_UNKNOWN continuation → Decision 8.
- Fresh-install seeding → Decision 11.
- Secret store → Decision 12.
- Legacy POST /start → Decision 15.

Test PG: postgres://pguser:***@172.17.0.1:5432/devpipe?sslmode=disable (override OVERSEER_TEST_PG_DSN).

Rules:
- Execution order follows the dependency chain. internal/resilience, internal/faults, internal/recovery, internal/invariants, internal/metrics, internal/clock and the internal/audit additions are pure domain packages (no database / net/http / gateway / os/exec). internal/backup is infrastructure (pgx allowed; no service imports).
- Hard invariants never weakened:
  - PostgreSQL is authoritative.
  - Durable intent precedes every non-idempotent side effect.
  - DELIVERY_UNKNOWN is never retried automatically.
  - Worker COMPLETE never means DONE.
  - Required validation and checkpoints gate DONE.
  - Detected corruption is reported, never auto-repaired.
- Every new retry loop goes through resilience.Do (no ad-hoc loops); AMBIGUOUS errors bypass retry.
- Fault points cost nothing when disabled. Production profile refuses OVERSEER_FAULTS.
- Read-only operations (scans, plans, verification, dry runs, diagnostics, readiness) run in READ ONLY transactions and are tested with DB fingerprints.
- Migration numbering (verify max+1 at execution), expected set:
  - 00112 app_config_snapshots + execution reproducibility / repository identity columns;
  - 00113 backup_records + restore_state;
  - 00114 recovery_plans + recovery_actions + dispatch_resolutions;
  - 00115 audit chain columns;
  - 00116 validation outcome values + log expiry;
  - 00117 integrity constraints (review);
  - 00118 driver_epoch monotonic trigger.

- Tests never contact a real Hermes Gateway, LLM or external network. Crashes are simulated in-process unless a task says real process. DB outages use the test TCP proxy; disk-full uses injected ENOSPC.

## Decisions taken in this plan (flag to ARCHITECT/user if any should change)
1. **Scope:** hardening only. New pure packages: resilience, faults, recovery, invariants, metrics, clock. One infrastructure package: backup. Existing services gain guards / classification. No new product features beyond the recovery / diagnostics / readiness surfaces the WBS requires.
2. **Fault injection** is compiled in but disabled by default. Tests enable it through faults.Enable. A real-process crash uses profile=test plus OVERSEER_FAULTS. The production profile rejects OVERSEER_FAULTS. Phase 16 SetStepHook stays as an adapter.
3. **Crash simulation:** in-process for most tests — a fault CRASH aborts the step, and the App is discarded without graceful shutdown; a new App starts on the same database, as in the Phase 16 restart rig. 18.129 and the live gate use a real subprocess and SIGKILL.
4. **Database outages** are simulated with a TCP proxy between the app and PostgreSQL (cut / refuse / restore / latency). The shared PG server is never restarted. "PostgreSQL restart" means the proxy drops every connection and refuses new ones for a window.
5. **Disk full** is simulated by injecting syscall.ENOSPC at write boundaries; the host disk is never filled. Classification uses errors.Is(err, syscall.ENOSPC), so a real ENOSPC behaves the same.
6. **Backup / restore** is a Go-native logical backup: COPY inside one REPEATABLE READ snapshot, a manifest and per-table hashes. There is no pg_dump on the box, and no extra tooling dependency is added.
   - Restore disables triggers via session_replication_role when the role is a superuser.
   - PITR (WAL archiving) belongs to the deployment. It is documented, and tested as "a restored point reconciles".
7. **Audit chain:** always on.
   - One chain per project plus a `system` chain for project-less events, each with a deterministic genesis.
   - Existing rows are chained once at startup by the Go serializer (single canonical implementation) under an advisory lock.
   - The immutability trigger stays; tamper tests disable it explicitly.
8. **DELIVERY_UNKNOWN resolution** (Phase 17 open decision): add VALIDATE_REPOSITORY_STATE (evidence only) and RESOLVE_DELIVERY {RESEND_AFTER_REVIEW, ACCEPT_REPOSITORY_STATE}. Both are high impact, need confirm + reason, are audited and idempotent, and are never automatic.
   - The dispatch row keeps DELIVERY_UNKNOWN forever; the resolution is a separate record.
   - This is what lets the 18.234 "Unit D … execution safely resumes" scenario proceed.
   - **Confirmed by the user (2026-10-12).**
9. **Validation outcomes:**
   - TEST_FAILURE and TIMEOUT route to FIX (the command ran; a hang is treated as a code failure), each kept as a distinct outcome.
   - EXECUTION_FAILURE and INFRA_ERROR take the bounded infrastructure retry, then recovery.
   - CANCELLED (shutdown) marks the run ABANDONED.
10. **Metrics:** in-house registry plus Prometheus text format at GET /metrics. No new module dependency. Label values come from closed sets only.
11. **Startup seeding** (Phase 17 open decision): global prompt templates and the default workflow are seeded idempotently at every start, so a fresh install can reach READY. Production readiness reports a failure if seeding failed.
12. **Secrets:** environment or file references; rotation is a file replacement. There is still no in-app secret store (Phase 17 Decision 8 stands). **Confirmed by the user (2026-10-12).**
13. **Authentication:** no multi-user authentication is added. In production the only accepted mode is `local` with `web.trusted_local: true` and a loopback bind. Anything else fails startup.
14. **Endurance:** the gate runs a scaled workload of a few minutes. The full 100 projects / 1,000 phases / 50,000 units runs on demand (OVERSEER_ENDURANCE=full) and is reported separately, not in the gate.
15. **Legacy POST /start** stays lifecycle-only. It gets a `Deprecation` header and a readiness-report warning. Removal is a user decision.
16. **Repository identity** = root commit + toplevel path + expected branch. An unrelated repository is detected by a root-commit mismatch; a moved path is surfaced as a mismatch for operator acceptance.
